# Git vs SVN: сравнение

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто указатель на коммит (ссылка). Создание ветки не копирует файлы, а лишь создаёт новую ссылку, поэтому операция мгновенная и не занимает места.

В SVN ветка — это физическая копия директории внутри репозитория (через `svn copy`). Это требует времени и дискового пространства, поэтому ветвление «дорогое».

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, нельзя.

Все коммиты отправляются на единый центральный сервер. Без сетевого соединения с сервером commit невозможен. Локально можно только редактировать файлы, но зафиксировать изменения в истории нет.

В Git коммит создаётся локально, сеть нужна только для синхронизации (push/pull).

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты в госсекторе и банках, где инфраструктура SVN уже настроена и миграция дороже, чем поддержка.
- Проекты с жёстким разграничением прав доступа к отдельным директориям (в SVN это делается проще).
- Работа с большими бинарными файлами без Git LFS.
- Команды, которым нужна простая централизованная модель без распределённых копий репозитория.
- Ситуации, где важен строгий последовательный номер ревизии (в Git хеши коммитов не монотонны).
